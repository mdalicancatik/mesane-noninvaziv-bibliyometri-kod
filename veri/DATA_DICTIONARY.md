# DATA DICTIONARY

The files in this folder are **derived data**. The raw Web of Science records are
proprietary and are not shared here (see `../README.md`, "Raw data").

---

## Fields removed, and why

The following fields are Clarivate proprietary content and have been stripped from
every file:

| Field | What it is | Why removed |
|---|---|---|
| `Abstract` | Publisher's copyrighted abstract | Copyright |
| `Keywords-Plus` | Clarivate-generated index terms | Proprietary derivation |
| `Cited-References` | Full reference string per record | Database content |
| `Affiliation` / `Affiliations` | Raw and Clarivate-normalised address fields | Proprietary normalisation |
| `Web-of-Science-Categories`, `Research-Areas` | Clarivate classification | Proprietary classification |

Titles and journal names were **also removed from the 5,000-record pool file**. A list of
5,000 titles could be regarded as redistribution of a substantial part of the database,
and the DOI alone is sufficient to reproduce the screening trail. Titles are retained in
the sample file, because the top 100 are published as a table in the article itself.

**Retained fields** are factual bibliographic identifiers (DOI, year, journal, document
type, citation count) and outputs generated by this study.

## `top100.json` — final sample (n = 100)

| Field | Description |
|---|---|
| `order` | Rank within the sample (1–100), citations descending; ties broken by earlier year |
| `rank` | Rank within the 5,000-record pool |
| `tc` | Web of Science citation count (as of the search date) |
| `year` | Publication year |
| `doi` | DOI |
| `title` | Title |
| `journal` | Journal |
| `type` | Web of Science document type |
| `first_author` | First author |
| `cat` | Technology category (1–5), assigned by the "principal technological contribution" rule |
| `screening_rationale` | Reason for inclusion; rule-based for 72 records, record-specific for 28 |
| `verdict` | Screening decision (all `IN` in this file) |
| `bladder_t` | Whether a bladder/urothelial term appears in the title |
| `tech_t` / `tech_a` | Technology terms matched in title / abstract |
| `diag_s_t` / `diag_s_a` | Strong diagnostic-framing terms matched in title / abstract |
| `diag_w_t` | Weak diagnostic-framing terms matched in the title |
| `mech_t` / `mech_a` | Mechanism / tumour-biology terms (exclusion signal) |
| `treat_t` / `treat_a` | Treatment terms (exclusion signal) |
| `tissue_t` / `tissue_a` | Tissue / histopathology terms (exclusion signal) |
| `invas_t` | Invasive / endoscopic method terms (exclusion signal) |
| `general_t` | Non-organ-specific general cancer terms |
| `mrd` | Minimal residual disease exception terms |

> `_t` = matched in the title, `_a` = matched in the abstract. These are **not abstract
> text**: they are expressions matched against the controlled term list in
> `../kod/thesaurus.py`, and are required in order to reproduce the screening decision.

**Note:** an earlier version contained a field named `cat_note` that carried a single
record's rationale on all 100 records. That field was removed and replaced by
`screening_rationale`, taken from the audit workbook by DOI match (100/100 matched).

## `sampleB.json` — sample B of the overlap analysis (n = 100)

A second sample built for robustness testing: same pool, first filtered by the technology
term list of the expanded query, then screened against the same criteria. Field structure
matches `top100.json` but without `cat` and `screening_rationale`.

Overlap between samples A and B is 98%.

## `pool5000_screening.json` — screening trail (n = 5,000)

The complete pool downloaded from the disease-block query in descending citation order,
with the screening decision for each record.

| Field | Description |
|---|---|
| `rank` | Pool rank (1 = most cited) |
| `doi` | DOI |
| `year` | Publication year |
| `tc` | Web of Science citation count |
| `type` | Web of Science document type |
| `verdict` | `IN` = meets criteria (n = 252) · `OUT` = does not (n = 4,700) · `SINIR` = flagged as borderline by the procedure and not adjudicated (n = 48) |

The pool spans 4,376–35 citations. The sample's lower bound is 63 citations, giving a
**safety margin of 28 citations**: no eligible record outside the pool could have more
than 35 citations, so the sample is demonstrably complete.

37 records in the pool are retracted publications (n = 33) or carry an expression of
concern (n = 4); they are identifiable from the `type` field. **All were excluded and
none entered the sample.** The most cited of these is a retracted 2024 review with 458
citations.

## `eligible252_identifiers.json` — records meeting the criteria (n = 252)

The network analyses were built on the full metadata of these 252 records. That full
metadata cannot be shared because it contains proprietary fields; only identifiers are
given here. A researcher with their own Web of Science access can retrieve the same
records from this DOI list.

Fields: `doi`, `year`, `tc`, `type`.

## `reference_set.json` — sensitivity-test reference set (n = 148)

The sensitivity of the search string was measured against a reference set that is
independent of the sample and was frozen in advance. The set comprises 148 unique
DOI-bearing references published 2016–2025, extracted from the reference lists of five
review articles.

| Field | Description |
|---|---|
| `dois` | 148 unique DOIs |
| `years` | DOI → publication year mapping |

This data is derived from the reference lists of published reviews; it is not Web of
Science database content.

Denominator correction: of the 148 references, 7 were not found in Web of Science /
SCI-EXPANDED and 5 did not meet the document-type criterion → **retrievable denominator
of 136**.
